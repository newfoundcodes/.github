# Security policy

Security work is part of maintaining reliable public infrastructure. Thank you for reporting
vulnerabilities responsibly.

## Supported versions

Support varies by project. Unless a repository states otherwise, security fixes target its latest
maintained release or default branch. Archived repositories and unsupported releases may not receive
updates.

## Report a vulnerability privately

Do not disclose an unpatched vulnerability in a public issue, discussion, pull request, commit, or
chat channel.

Use GitHub's **Report a vulnerability** option in the affected repository when private vulnerability
reporting is available. Otherwise email
[hello@newfoundcodes.com](mailto:hello@newfoundcodes.com) with the subject
`Security report: <project name>`.

Include as much of the following as possible:

- The affected project, version, commit, and configuration.
- The vulnerability's impact and realistic attack scenario.
- Reproduction steps or a minimal proof of concept.
- Relevant logs, traces, or screenshots with secrets removed.
- Suggested mitigations or fixes, if known.
- Whether the issue has been disclosed anywhere else.

We will acknowledge the report as soon as practical, investigate it, coordinate a fix and release
when warranted, and discuss an appropriate disclosure timeline with the reporter. Please allow time
for maintainers to verify and remediate the issue before publishing details.

## Scope

This policy covers software and infrastructure maintained by the Newfoundcodes organization.
Third-party services, dependencies, forks, and unsupported deployments should normally be reported
to their respective maintainers, though we welcome notice when they directly affect a Newfoundcodes
project.

Reports made in good faith to improve project security are welcome. Do not access unrelated data,
degrade services, perform denial-of-service testing, or use social engineering while researching a
report.
